# แนวทางใช้ KM กับบอต

ปรับปรุง: 2026-11-28

เป้าหมายคือให้บอตตอบคำถามการใช้งาน FalCon2CP และรวบรวม feedback ได้อย่างสม่ำเสมอ
สถานะปัจจุบันมีฐานเอกสารเท่านั้น ยังไม่ได้เลือกช่องทางบอต ระบบรับเรื่อง หรือการเชื่อมต่ออัตโนมัติ

## ชุดเอกสารและลำดับใช้งาน

| ไฟล์ | หน้าที่ |
|---|---|
| [USER_GUIDE.md](USER_GUIDE.md) | วิธีใช้งานและข้อจำกัดที่ผู้ใช้ควรรู้ |
| [FAQ.md](FAQ.md) | คำตอบสั้นและขั้นตอนตรวจอาการทั่วไป |
| [FEEDBACK.md](FEEDBACK.md) | คำถามรับเรื่อง แม่แบบ และการแยกสถานะการส่ง |
| [ONLINE.md](ONLINE.md) | วิธีทำ/อัปเดตแผนที่ สำหรับคำถามด้านแผนที่ |
| [PROJECT_SUMMARY.md](PROJECT_SUMMARY.md) | บริบททางเทคนิคและกติกาสำหรับผู้ดูแล |

เริ่มตอบจากคู่มือและ FAQ ก่อน ใช้สรุปโครงการเมื่อจำเป็นต้องอธิบายแหล่งข้อมูลหรือส่งต่อผู้ดูแล
หากบอตอ่าน GitHub ได้ ให้อ้างเอกสารที่ merge เข้า `main` แล้ว พร้อมเก็บ commit/วันที่ของชุดเอกสารที่ใช้
หากอัปโหลดไฟล์เข้าแหล่งความรู้ของบอตเอง ต้องอัปโหลดใหม่หลังเอกสารเปลี่ยน; การ merge ไม่ได้อัปเดตบอตทุกแพลตฟอร์มให้เอง

## ข้อความตั้งต้นสำหรับบอต

ข้อความต่อไปนี้เป็นแม่แบบสำหรับนำไปตั้งค่าในบอตที่เลือก ไม่ใช่การเปิดใช้งานบอตในเว็บ:

```text
คุณเป็นผู้ช่วยการใช้งาน FalCon2CP ตอบภาษาไทย สั้น ชัดเจน ใช้ชื่อปุ่มตามแอป
อ้างอิง USER_GUIDE.md และ FAQ.md ของชุด KM ที่ได้รับก่อนตอบ
ตอบวิธีทำเป็นขั้นตอนสั้น ๆ และระบุไฟล์/หัวข้ออ้างอิงที่เกี่ยวข้อง
หากไม่พบข้อมูล ให้บอกว่ายังไม่มีข้อมูลในคู่มือและถามรายละเอียดที่จำเป็น
อย่าแต่งชื่อปุ่ม ฟีเจอร์ เวอร์ชัน หรือผลทดสอบอุปกรณ์ที่ไม่มีในเอกสาร
อย่าสรุปว่าอาการเป็นบั๊กยืนยันแล้วโดยยังไม่มีผลทำซ้ำ
เมื่อผู้ใช้ให้ feedback ให้ใช้ FEEDBACK.md และถามเฉพาะข้อมูลที่ขาด
แยกแบบร่างออกจากรายการที่ส่งสำเร็จ ห้ามอ้างว่าบันทึกหรือส่งให้ทีมแล้วโดยไม่มีผลตอบรับจริง
อย่าขอรหัสผ่าน token หรือข้อมูลเส้นทางจริงที่ไม่จำเป็น
```

## รูปแบบคำตอบการใช้งาน

1. ตอบสิ่งที่ต้องทำก่อน เช่น “ปลดล็อกเป็น 🔓 ก่อนครับ”
2. ให้ขั้นตอนที่ทำต่อได้ 1–4 ขั้น
3. ระบุข้อจำกัดที่เกี่ยวข้อง เช่น % บนจอไม่เปลี่ยนมาตราส่วนพิมพ์
4. อ้างชื่อเอกสารและหัวข้อ แสดงลิงก์ที่มีอยู่จริงเมื่อช่องทางรองรับ

ถ้าข้อมูลไม่พอ ให้ถามครั้งละประเด็น เช่น รูปแบบแผนที่หรือสถานะล็อกก่อนถามเวอร์ชันระบบทั้งหมด
อย่าแนะนำ CLEAR, ล้างข้อมูลเว็บไซต์ หรือนำเข้าไฟล์ทับข้อมูล เป็นขั้นตอนแรกของการแก้ปัญหา

## ขั้นตอนนำไปใช้

1. ให้ผู้ดูแลตรวจคู่มือกับแอปและแก้เนื้อหาก่อน merge
2. ใช้ชุดเอกสารทดลองถาม–ตอบกับบอต โดยยังไม่ต้องมีระบบรับเรื่องอัตโนมัติ
3. เลือกช่องทางบอตและที่เก็บ feedback ตามการใช้งานจริง
4. เชื่อมการอ่านเอกสารและการรับเรื่อง แล้วตรวจผลส่งสำเร็จจากระบบปลายทาง
5. เมื่อเปลี่ยนฟีเจอร์ ให้อัปเดตคู่มือ/FAQ และชุดความรู้ที่บอตใช้ด้วย

การเลือกช่องทางและระบบรับเรื่องเป็นงานขั้นถัดไป เอกสารชุดนี้ไม่สร้างบัญชีบริการ ส่งข้อความ หรือเปิด Issue ให้เอง

## คำถามตรวจความพร้อมก่อนใช้งาน

| คำถามทดลอง | ประเด็นที่คำตอบต้องถูก |
|---|---|
| สนามบินเปิดตรงไหน? | Layers มุมขวาบน > AIRPORTS |
| สร้างเส้นทางสำรองอย่างไร? | ต้องมี PZ/LZ ของเส้นทางหลัก แล้วเลือกเส้นทางสำรอง |
| Add ROUTE คือสร้างเส้นทางสำรองหรือไม่? | เป็นการเพิ่มจุด |
| เพิ่มจุดแล้ว LZ ไม่ย้าย ทำไม? | จุดใหม่แทรกก่อน LZ ที่มีอยู่ |
| ลากจุดหรือกล่องไม่ได้ ทำอย่างไร? | ตรวจ 🔒 และปลดล็อกก่อน; การลากสัญลักษณ์จุดต้องอยู่โหมด On MAP ด้วย; ไม่ยืนยันว่าเป็นบั๊กทันที |
| ไม่เห็นแผนที่ JOG / TPC ทำอย่างไร? | แอปเปิดบน OSM ก่อน ให้กด 🔑 LOGIN ในหมวด MAP เพื่อปลดล็อก JOG/TPC |
| เปลี่ยน % แล้วพิมพ์ใหญ่ขึ้นไหม? | % มุมมองกระดาษปรับเฉพาะจอ |
| ซูมด้วยนิ้วแต่ % ไม่เปลี่ยน? | ต้องเปิดมุมมองกระดาษและแตะบนพื้นที่แผนที่ |
| ทำไม SHOW กลับมาเมื่อสลับรูปแบบ? | ค่า SHOW แยกตามรูปแบบ |
| Offline ใช้แผนที่และ ALT ได้ทุกพื้นที่ไหม? | แยกพื้นที่ที่เคย cache กับไฟล์ IMPORT MAP; ALT offline ใช้ปุ่ม ⛰ โหลด Elevation |
| ทำดราฟแผน Word/PDF ได้ไหม? | ใช้ปุ่ม DOC PLAN ในหมวด FUNCTION ส่งออก Word (.docx) / PDF / PNG 2 หน้า |
| EXPORT แล้วเอากลับมาได้เหมือนเดิมทุกอย่างไหม? | ไม่รับประกันตำแหน่งกล่อง/ค่าหน้าจอ/การแยกสองเส้นทาง |
| CLEAR แล้ว UNDO ได้ไหม? | CLEAR ล้างประวัติ UNDO/REDO |
| ช่วยรับ feedback นี้ไว้ด้วย | สรุปข้อมูลและสถานะจริง; ไม่สร้างเลขอ้างอิงขึ้นเอง |
| มีโหมดที่ไม่ได้ระบุในคู่มือไหม? | บอกว่ายังไม่มีข้อมูล แทนการแต่งฟีเจอร์ |

ก่อนเปิดใช้งานจริง ให้ตรวจเพิ่มบนอุปกรณ์เป้าหมาย เช่น Safari บน iPad/iPhone
การอ่านคู่มือหรือผ่านคำถามตัวอย่างไม่ใช่หลักฐานว่าฟีเจอร์ผ่านการทดสอบบนอุปกรณ์จริงแล้ว
